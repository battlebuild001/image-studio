# Content Studio for Windows

Windows 10·11 64비트에서 설치하거나 압축을 풀어 실행하는 별도 프로그램입니다. 기존 대본·음성·이미지·자막·한 번에 제작·검수·업로드 화면을 앱 안에서 사용합니다. Chrome, Node.js 또는 로컬 서버를 별도로 설치하지 않습니다.

## 배포 파일

- `Content-Studio-Setup-<버전>-x64.exe`: 일반 설치 프로그램입니다. 사용자 계정에 설치하며 설치 위치와 바로가기를 선택합니다.
- `Content-Studio-<버전>-Windows-x64-Portable.exe`: 설치 없이 실행하는 파일입니다. 실행할 때 앱을 임시 폴더에 풉니다.
- `Content-Studio-<버전>-Windows-x64.zip`: 압축을 모두 푼 뒤 `ContentStudio.exe`를 실행합니다. 압축 안에서 실행 파일만 따로 옮기지 않습니다.
- `desktop-release.json`: 파일 크기·SHA-256·포함된 앱 소스 버전을 기록한 검증 자료입니다.
- `Content-Studio-Source-<버전>.zip`: 다시 빌드할 수 있는 앱·빌드 스크립트·테스트 소스입니다. 사용자 프로젝트·API 키·설치된 개발 의존성은 포함하지 않습니다.

설치형과 휴대용은 같은 앱 데이터 폴더를 사용합니다. 휴대용 실행 파일 옆에 설정이나 API 키를 저장한다는 뜻은 아닙니다. 업데이트나 제거 전에 필요한 프로젝트를 별도 폴더로 저장해 두세요. 앱 제거는 개인 프로젝트 폴더나 앱 데이터 폴더를 자동 삭제하지 않도록 설정했습니다.

현재 배포는 코드 서명 인증서가 없는 **미서명 빌드**입니다. Windows의 보안 확인이 표시될 수 있습니다. 배포된 파일 이름·출처와 제공된 SHA-256을 확인하세요. 이 빌드에는 자동 업데이트 기능이 없으며 새 버전은 직접 설치합니다.

## 저장과 기존 작업 가져오기

브라우저의 저장소와 데스크톱 프로그램의 저장소는 서로 독립적입니다. 웹앱에서 프로젝트 저장/백업으로 내려받은 `.bth.json` 파일을 프로그램의 프로젝트 열기로 가져오세요. 대본·이미지·음성·자막을 포함한 기존 백업 형식을 유지합니다.

프로그램의 프로젝트 저장은 사용자가 고른 PC 폴더를 대상으로 합니다. 일반 편집 중 자동 저장은 앱의 데이터 폴더에 남습니다. 내보낸 MP4·PNG·TXT 등은 저장 창에서 위치를 고를 수 있습니다. 프로젝트·미디어와 API 인증 정보는 분리해서 관리합니다.

API 키를 PC에 기억하도록 선택한 경우 운영체제의 보안 저장 기능으로 암호화합니다. API 키·Google 인증 정보는 프로젝트 파일과 배포 파일에 포함하지 않습니다. 운영체제의 안전한 저장 기능이 제공되지 않는 환경에서는 평문으로 대체 저장하지 않습니다.

AI 생성과 YouTube 업로드에는 인터넷과 해당 서비스 계정이 필요합니다. API 사용료와 YouTube의 채널 업로드 제한은 해당 서비스 정책을 따릅니다. 앱 시작이나 프로젝트 열기만으로 유료 생성·업로드를 실행하지 않습니다.

## YouTube 연결

설치형 앱은 Google 로그인을 운영체제의 기본 브라우저에서 진행합니다. 웹사이트용 OAuth 설정과 구분해서 Google Cloud에서 **데스크톱 앱용 OAuth 클라이언트**를 만들고, 내려받은 설정 JSON을 앱에서 선택해 가져옵니다. 실제 설정 파일이나 API 키를 채팅으로 보낼 필요는 없습니다.

Google 계정과 채널을 선택한 뒤 앱으로 돌아오면 기존 업로드·예약·재생목록 기능을 사용합니다. 재생목록 추가 권한은 해당 기능을 명시적으로 연결할 때 요청합니다. 이 프로그램이 Google의 앱 승인이나 계정 권한, 채널 업로드 한도를 대신 해제하지는 않습니다.

## 개발·빌드

개발자는 Node.js 22 이상에서 저장소의 고정 의존성을 설치합니다.

```sh
npm ci
node scripts/desktop-build.mjs --win --source-archive --output .desktop-build
```

Windows 빌드는 x64 NSIS 설치 파일·휴대용 EXE·ZIP을 함께 만듭니다. Linux에서도 공식 Electron Windows 배포와 NSIS 빌드 도구를 사용해 교차 패키징할 수 있습니다. 위 빌드 스크립트는 고정한 electron-builder의 공식 `UninstallerReader`를 사용해 미서명 제거 프로그램을 추출하며, Linux에서 Windows 스텁을 실행하지 않습니다. Windows PC에는 Wine이 필요하지 않습니다. 네트워크가 제한된 실행 환경에서는 기존 프록시와 CA 신뢰 설정을 그대로 사용하세요.

```sh
node scripts/desktop-build.mjs --win --verify-only --output .desktop-build
node scripts/desktop-build.mjs --linux-smoke --output .desktop-linux
```

검증은 Windows PE 헤더, x64 앱 실행 파일, 휴대용 ZIP의 전체 런타임, 앱 ASAR에 포함된 정적 파일·메인 코드의 실제 바이트, 인증 정보·프로젝트 파일 미포함 여부를 확인합니다. Linux 스모크 빌드는 같은 Electron 앱의 실행·저장·복구를 점검하는 용도입니다. Windows 실기기 실행·코드 서명·실제 Google 로그인·실결제 AI 품질을 이 파일 검증만으로 확인했다고 표현하지 않습니다.

소스 ZIP을 풀어 `npm ci` 후 같은 빌드 명령을 실행할 수 있습니다. `npm test`는 계정·실제 결제 API 없이 실행하는 단위 검증입니다. Electron 런타임 검증에는 GUI 또는 Linux의 Xvfb가 필요합니다. 최종 Windows 확인은 새 사용자 계정에서 설치·실행, 프로젝트 저장 후 재시작과 다시 열기, 파일 내보내기, 제거 후 프로젝트 보존을 확인합니다. 실제 Google 연결은 테스트 계정으로 별도 확인하며, 비용이 드는 이미지·음성 생성과 공개 업로드는 사용자가 명시적으로 실행할 때만 확인합니다.
